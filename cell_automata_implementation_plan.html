1. Executive Summary & Core Objectives

The CA Studio application is a professional workstation tool built with Flutter for Linux Desktop designed to simulate large-scale 2D cellular automata. It resolves the computational and rendering bottlenecks of high-density grids while delivering an intuitive desktop interface faithful to the UX specifications.

The Three Architectural Pillars
1. Decoupled Compute (Background Dart Isolate): Evaluates cellular transitions across up to 960,000 cells every 10–100 ms using zero-allocation double buffers.
2. Zero-Jank GPU Fragment Shader (Impeller / Vulkan): Translates the raw state buffer into a 2D texture (sampler2D) and executes exactly one draw call with signed distance fields (SDF) for silky 60–144 FPS pan, zoom, and interaction.
3. Embedded Rule Editor Modal Dialog: Reuses the full grammar lexer, recursive descent parser, AST evaluator, functions palette, and 3x3 Moore neighborhood matrix from the RuleEditor codebase.

2. System Architecture Blueprint

3. Dynamic Grid Sizing & Strict 1:1 Aspect Ratio Preservation

The viewport canvas enforces uniform aspect ratio scaling to ensure that cells always render as exact 1:1 geometric squares or Euclidean circles, preventing any stretching into non-square rectangles or ellipses regardless of grid dimensions or window aspect ratio.

Inverse Proportionality Principle: Grid Size vs. Cell Visual Size
When the user adjusts grid dimensions (Width × Height in cells) in the sidebar:
  • Smaller Grid Dimensions (e.g. 32 × 32 or 64 × 64 cells): Each individual cell renders significantly larger on screen (e.g. 20–35 px), showing prominent geometries, distinct inter-cell gaps, and easy target areas for mouse drawing.
  • Larger Grid Dimensions (e.g. 1200 × 800 cells): Each cell renders proportionally smaller (≈ 1.5 px at maximum density), packing hundreds of thousands of cells neatly across the viewport.

1:1 Cell Geometry & Viewport Fitting Mathematics

Given the available viewport dimensions $(W_v \times H_v)$ and user-specified grid dimensions $(C \text{ columns} \times R \text{ rows})$:

1. Uniform Cell Side Length (Pixels): S = min( W_v / C, H_v / R ) ==> Guarantees each cell is an exact S x S square 2. Active Grid Rendered Bounds on Screen: W_active = C * S H_active = R * S 3. Symmetrical Centering Offsets (Letterboxing / Pillarboxing): offset_x = (W_v - W_active) / 2 offset_y = (H_v - H_active) / 2 4. Mouse-to-Cell Coordinate Translation (with Margin Clamping): cell_x = floor( (x_mouse - offset_x) / (S * zoom) ) cell_y = floor( (y_mouse - offset_y) / (S * zoom) ) (Events with cell_x < 0 or cell_x >= C or cell_y < 0 or cell_y >= R are cleanly clipped)
GPU Shader Guarantee (No Ellipses / Distortions)

The fragment shader uniform u_resolution receives $(W_{\text{active}}, H_{\text{active}})$, matching the exact aspect ratio of the grid $(C / R)$.

Inside the shader, UV coordinates within each cell evaluate as fract(uv * u_grid_size). Because each cell is an exact $S \times S$ square in screen space, the Signed Distance Field (SDF) length(cellUV - 0.5) evaluates isotropically, rendering true Euclidean circles without oval distortion.

Uniform Zoom & Pan Preservation

Zooming applies a single uniform multiplier $Z$ equally to both axes ($S' = S \times Z$), preserving the 1:1 proportion at all zoom levels.

The unused screen space around the active grid forms neat letterbox/pillarbox margins rendered with the dark workstation background (#070b12), maintaining focus on the cellular automata.

5. Isolate Communication & Zero-Copy Protocol

Dart isolates maintain isolated heaps. To avoid deep-copy memory latency of 960,000 bytes every 10–30 ms, the system utilizes TransferableTypedData for O(1) pointer transfer.

Phase Message / Channel Description & Responsibilities
1. Handshake ReceivePort → SendPort UI thread spawns isolate with its SendPort. Isolate replies with its own command SendPort.
2. UI Commands StartSim, PauseSim, SetRule, Resize, Randomize UI dispatches lightweight control objects to isolate. Simulation tick begins or updates immediately on resize.
3. Frame Emission SimulationFrameMessage via TransferableTypedData Isolate wraps Uint8List into TransferableTypedData.fromList([nextBuffer]) and sends to UI port in O(1) time.
4. UI Ingestion materialize().asUint8List() → ui.Image UI thread converts bytes into hardware texture via ui.ImmutableBuffer and ImageDescriptor.raw.
5. Backpressure Drop-frame policy If UI is busy during window resize, intermediate frames drop cleanly. The UI always paints the freshest state.
